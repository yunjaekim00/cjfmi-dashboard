# 경제 지표 대시보드

한국은행 ECOS 와 FRED 데이터를 모아 보는 거시 경제 대시보드입니다.
현재는 **원/달러 환율**만 구현되어 있고, 지표를 추가하기 쉽도록 구조를 잡아 두었습니다.

- **0. 종합 지표** — 기준금리 · 국고채 3년/10년 · 미국 10년물 · 원/달러 · 원/엔 ·
  KOSPI · KOSDAQ · S&P 500 요약 카드
- **1. 금리** — 정책금리(한·미·유로) / 한국 단기금리 / 한국 채권금리
- **2. 환율** — 원/달러 · 원/엔(100엔) 매매기준율
- **3. 주간 모니터링** — 지난 일주일 금융시장 뉴스(Bloomberg · 국제금융센터)를 Claude 가 읽고
  [주간이슈] 3건 · [시장반응] 분야별 한 문장으로 정리. 참고 보고서 서식(CJ ONLYONE) 그대로

화면을 띄워 두면 **5분마다 자동으로 최신 값을 확인**합니다. 탭을 다시 열거나
네트워크가 복구됐을 때도 한 번 더 확인합니다.

## 1. 한국은행(ECOS) API 인증키 발급 — 단계별

매매기준율(한국은행 고시 환율)을 받으려면 ECOS 인증키가 필요합니다. 무료이고, 심사 없이 바로 발급됩니다.

1. **ECOS 사이트 접속** — <https://ecos.bok.or.kr>
2. **회원가입** — 우측 상단 `회원가입`. 이메일 인증까지 완료해야 합니다.
3. **로그인**
4. 상단 메뉴에서 **`오픈API`** → **`인증키 신청`** 으로 이동
5. **신청서 작성**
   - 활용 용도: 예) `개인 학습용 경제지표 대시보드`
   - 사용 URL: 예) `http://localhost:3000` (배포하면 실제 도메인으로 수정)
   - 이메일: 가입한 이메일
6. **신청** 버튼을 누르면 **즉시 발급**됩니다. 발급된 키는
   `오픈API` → `인증키 관리`(마이페이지)에서 다시 확인할 수 있고, 가입 이메일로도 발송됩니다.
7. 발급받은 키를 프로젝트 루트의 `.env.local` 에 넣습니다.

```bash
cp .env.local.example .env.local
```

```dotenv
ECOS_API_KEY=여기에_발급받은_키
```

8. **개발 서버를 재시작**합니다. `.env.local` 은 서버 시작 시점에만 읽힙니다.

> ECOS 호출 한도는 두 가지입니다.
> - **하루 100,000회** (인증키당)
> - **3분간 300회** — 넘기면 `ERROR-602` 로 **30분간 차단**됩니다. 이쪽이 훨씬 걸리기 쉽습니다.
>
> 아래 [호출 한도 관리](#호출-한도ecos-error-602-관리)를 참고하세요.

> 키가 없어도 앱은 동작합니다. FRED(뉴욕 종가)만 그려지고, 화면 상단에
> "일부 데이터를 불러오지 못했습니다" 안내가 뜹니다.

### FRED 키 (선택)

지금 화면에는 FRED 데이터가 없지만, 미국 10년물·연준/ECB 정책금리를 붙일 때 쓰려고
클라이언트(`lib/sources/fred.ts`)를 남겨 뒀습니다. `FRED_API_KEY` 는 **없어도 됩니다** —
비워 두면 키가 필요 없는 `fredgraph.csv` 엔드포인트를 씁니다. 공식 JSON API 를 쓰려면
<https://fredaccount.stlouisfed.org/apikeys> 에서 발급받으세요.

## 1-1. 주간 모니터링 탭 — 두 가지 방식

"3. 주간 모니터링" 탭은 지난 일주일(어제까지 끝난 7일) 금융시장 뉴스를 Claude 가 읽고
보고서 문장으로 정리해 보여준다. 만드는 방법은 둘이고, **파일이 있으면 늘 파일이 우선**이다.

### 방식 A. Claude Code 로 만들기 (추천 — API 키·크레딧 불필요)

Claude Code(구독에 포함)에서 프로젝트 폴더를 열고 **채팅 입력창에** `/weekly` 를 친다 — 폴더나 URL 이 아니라
Claude Code 의 슬래시 명령이다. Claude Code 가 Bloomberg·국제금융센터를 검색해 `data/YYMMDD-weekly-brief.json`
(YYMMDD = 실행일, 예 `261102-weekly-brief.json`)을 쓰고 검증까지 한다. 개발 서버가 떠 있으면 새로고침만 하면
탭에 반영된다. 지난 파일은 지우지 않고 날짜별로 쌓이며, **탭은 파일명이 가장 늦은 것**을 보여준다.

```
/weekly              # 어제까지 끝난 7일
/weekly 2026-10-30   # 종료일 지정
```

- 절차는 `.claude/skills/weekly/SKILL.md`, 보조 스크립트는 `scripts/weekly-indicators.mjs`(지표 주간 변동)와
  `scripts/weekly-validate.mjs`(파일 검증).
- 배포본(Vercel)에 반영하려면 그 파일을 커밋해 푸시해야 한다 (`next.config.ts` 가 `data/` 를 함수 번들에 포함한다).
- 매주 자동으로 돌리려면 Claude Code 의 클라우드 routine(`/schedule`)에 "/weekly 실행 후 커밋·푸시"를 맡기면 된다.
  저장소를 Claude 계정에 연결(<https://claude.ai/connect-github>)해야 한다.

### 방식 B. 서버가 Claude API 로 만들기

파일이 없고 `ANTHROPIC_API_KEY` 가 있으면 탭을 열 때 서버가 직접 만든다 (1~2분, 하루 한 번 캐시).
API 크레딧은 claude.ai 구독과 **별도**로 <https://platform.claude.com> → Plans & Billing 에서 충전한다.

```dotenv
ANTHROPIC_API_KEY=sk-ant-…
# (선택) 모델을 바꾸려면. 비우면 claude-opus-5-5
WEEKLY_MODEL=
```

- 비용은 모델 토큰에 웹 검색 건당 $0.01 이 더해져 회당 수백 원 수준. "다시 생성" 버튼은 캐시를 비우고 새로 만든다.
- 뉴스 출처 도메인은 `lib/weekly.ts` 의 `NEWS_DOMAINS` (기본: Bloomberg, 국제금융센터 + 보충용 연합뉴스, 연합인포맥스).
- 안전 분류기가 요청을 거절하면 Anthropic 이 권장하는 다른 모델로 서버에서 자동 재시도한다
  (`fallbacks: "default"`). 끄려면 `lib/weekly.ts` 의 `betas` / `fallbacks` 두 줄을 지우면 된다.

### 공통

- 둘 다 없으면 탭에 안내문만 뜨고 나머지 탭은 그대로 동작한다.
- 모델 호출 없이 **레이아웃만 보려면** `http://localhost:3000/?tab=weekly&sample=1` — 참고 보고서 원문이 그대로 뜬다.

## 1-2. Vercel 배포 시 환경변수

**`.env.local` 은 `.gitignore` 에 걸려 있어 GitHub 에 올라가지 않습니다.**
따라서 Vercel 에는 따로 넣어 줘야 합니다.

1. <https://vercel.com> → 해당 프로젝트 → **`Settings`** → **`Environment Variables`**
2. `Key` = `ECOS_API_KEY`, `Value` = 발급받은 인증키 (주간 모니터링을 쓰면 `ANTHROPIC_API_KEY` 도)
3. 적용 환경은 **Production / Preview / Development 세 개 모두** 체크
4. **`Save`**
5. **`Deployments`** 탭 → 최신 배포의 `⋯` → **`Redeploy`**
   (환경변수는 빌드 시점에 주입되므로, 저장만 하고 재배포하지 않으면 반영되지 않습니다)

> ECOS 인증키 신청서의 "사용 URL" 에 배포 주소(`https://<프로젝트>.vercel.app`)도
> 추가해 두는 편이 안전합니다.

## 3. 데이터 출처

통계표·항목 코드는 ECOS `StatisticItemList` API 로 **실제 응답을 확인한 값**입니다.
(회사채 AA- 는 `010300000` 이고 `010320000` 은 BBB- 라 헷갈리기 쉽습니다.)

| 계열 | 출처 | 식별자 |
|---|---|---|
| 원/달러 매매기준율 | ECOS | `731Y001` / `D` / `0000001` |
| 원/엔(100엔) 매매기준율 | ECOS | `731Y001` / `D` / `0000002` |
| 한국은행 기준금리 | ECOS | `722Y001` / `D` / `0101000` |
| 콜금리(1일, 전체거래) | ECOS | `817Y002` / `D` / `010101000` |
| CD(91일) | ECOS | `817Y002` / `D` / `010502000` |
| 국고채(3년) | ECOS | `817Y002` / `D` / `010200000` |
| 국고채(10년) | ECOS | `817Y002` / `D` / `010210000` |
| 회사채(3년, AA-) | ECOS | `817Y002` / `D` / `010300000` |
| KOSPI지수 | ECOS | `802Y001` / `D` / `0001000` |
| KOSDAQ지수 | ECOS | `802Y001` / `D` / `0089000` (2003년~) |
| 미국 국채 10년물 | FRED | `DGS10` |
| 미국 연방기금금리(실효) | FRED | `DFF` |
| ECB 예금금리 | FRED | `ECBDFR` |
| S&P 500 | FRED | `SP500` (라이선스상 최근 10년치만 제공) |

1995년부터 일별로 받아 오고, 휴장일은 선으로 이어 그립니다.

### 기준금리 카드가 일별 계열을 쓰는 이유

ECOS 의 월별 기준금리(`722Y001` / `M`)는 그 달이 끝나야 채워집니다. 월별을 쓰면
금리를 인상한 날부터 최대 한 달 동안 카드가 옛 값을 보여주게 되어, 값과 날짜는
**일별** 계열에서 가져오고 변화량만 "전월대비"로 계산합니다
(`lib/catalog.ts` 의 `compareMonthsBack`).

### 갱신 구조

```
브라우저 ──5분마다──▶ /api/exchange-rate?since=…  ──▶ ECOS
                         (수백 바이트)                (실제 호출은 10분에 한 번)
```

- 첫 화면은 서버에서 렌더해 바로 보여 줍니다.
- 이후에는 브라우저가 `?since=` 로 **최근 며칠치만** 받아 이어 붙입니다
  (전체 9,800건은 다시 받지 않습니다).
- ECOS 응답은 5년 단위로 나눠서 캐시합니다. 한 번에 30년치를 받으면 4MB 가 넘어
  Next.js 의 fetch 캐시(항목당 2MB) 에 들어가지 않고, 그러면 폴링할 때마다
  한국은행 API 를 그대로 때리게 됩니다. 지난 구간은 30일, 최신 구간만 10분 캐시입니다.
- 결과적으로 방문자가 몇 명이든 외부 API 호출은 **10분에 한 번**입니다.

### 호출 한도(ECOS ERROR-602) 관리

ECOS 응답은 한 건이 400바이트가 넘어서, 일별 30년치를 한 번에 받으면 4MB 가 됩니다.
Next.js 의 fetch 캐시는 **항목당 2MB** 를 넘는 응답을 저장하지 않으므로 조회를 연 단위로
쪼개야 하는데, 잘게 쪼개면 이번엔 **3분간 300회** 한도에 걸립니다. 그 사이를 맞춘 설정입니다.

| | 값 |
|---|---|
| 조회 창 크기 | **10년** (일별 약 2,600건 ≈ 1.2MB — 2MB 캐시 한도 아래) |
| 계열당 창 수 | 4개 (1995 / 2005 / 2015 / 2025), 자료 시작이 늦으면 그만큼 적음 |
| ECOS 계열 수 | 10개 |
| **콜드 1회 전체 조회** | **39회** |
| **폴링 1회 (`?since=`)** | **10회** (프로세스 캐시 적중 시 0회) |
| **브라우저 새로고침** | **0회** (서버 데이터가 5분 안쪽이면 조회 안 함) |

여러 겹으로 막습니다.

**서버 쪽**

1. **증분 조회** — 폴링은 `?since=` 로 **조회 구간 자체를 좁힙니다.** 예전에는 4KB 짜리
   응답 하나를 만들려고 전체 이력을 다시 받아 필터링해서 56회를 썼습니다.
2. **프로세스 캐시** — 파싱된 결과를 `globalThis` 에 들고 있습니다. `.next` 를 지우거나
   개발 중 핫리로드로 Next.js fetch 캐시가 날아가도, 같은 프로세스 안이면 네트워크를
   타지 않습니다. (지난 구간 6시간 / 최신 구간 10분)
3. **동시 요청 합치기** — 같은 조회창을 동시에 요청하면 진행 중인 약속을 함께 기다립니다.
   새로고침이 몰리면 캐시가 채워지기 전에 같은 요청이 여러 번 나갑니다.
4. **자체 상한** — 한 프로세스가 3분간 120회를 넘기면 ECOS 를 부르지 않고 즉시
   실패시킵니다. 한도에 걸려 30분 차단되는 것보다 낫습니다.
5. **서킷 브레이커** — `ERROR-602` 를 한 번 맞으면 30분간 **남은 요청을 아예 보내지
   않습니다.** 차단된 상태에서 계속 때리면 상황만 나빠집니다.

**브라우저 쪽**

6. **새로고침해도 조회하지 않음** — 서버가 5분 안에 받아온 데이터면 뜨자마자 다시 묻지
   않습니다. 예전에는 새로고침 한 번마다 조회가 나가서, 화면을 확인하는 것만으로
   한도가 쌓였습니다.
7. **최소 간격 60초** — 탭 전환(`visibilitychange`)이든 타이머든, 그보다 자주 묻지
   않습니다. (사용자가 직접 누른 `새로고침` 버튼만 예외)
8. **폴링 주기 = 캐시 수명(10분)** — 서버가 10분 캐시하는데 5분마다 물으면 절반이
   헛걸음입니다.

**ECOS 응답 자체의 문제**

ECOS 는 멀쩡한 구간에도 간헐적으로 `INFO-200`("해당하는 데이터가 없습니다")을 돌려줍니다.
그대로 두면 **빈 응답이 fetch 캐시에 최대 30일 박혀** 차트에서 과거 구간이 통째로
사라집니다. 과거 창이 비어 있으면 캐시를 우회해 한 번 다시 묻고, 그래도 비어 있으면
캐시하지 않습니다.

개발 중에는 서버 로그에 실제 호출 수가 찍힙니다.

```
[ecos] 실제 호출 32회 · 프로세스 캐시 적중 0회 (전체)
[ecos] 실제 호출 8회 · 프로세스 캐시 적중 0회 (증분: 2026-08-17 이후)
```

> **주의**: Vercel 은 **배포할 때마다 Data Cache 키가 바뀌어** 첫 요청이 항상 콜드입니다.
> 즉 배포 1회 = ECOS 32회입니다. 짧은 간격으로 여러 번 배포하면 한도에 걸릴 수 있습니다.

### 전송량

계열이 12개라 원본 그대로 보내면 브라우저로 수 MB 가 갑니다. 차트가 실제로 그릴 수
있는 점은 화면 폭만큼(약 1,400개)이라, **최근 5년은 일별 원본 그대로**, 그 이전은
LTTB 로 솎아서(`lib/downsample.ts`) 계열당 2,000~2,700점으로 줄입니다.
LTTB 는 균등 간격 샘플링과 달리 1997년 환율 급등 같은 극값을 잘라내지 않습니다.

| | 크기 |
|---|---|
| 첫 로드 (14계열 전체) | 1.1MB → gzip **150KB** |
| 폴링 1회 (`?since=`) | **약 4KB** |

### 지표를 추가하려면

전부 [lib/catalog.ts](lib/catalog.ts) 한 파일에서 끝납니다.

1. `SERIES` 에 계열 정의를 한 줄 추가합니다.
2. 카드가 필요하면 `CARDS` 에, 차트가 필요하면 `CHARTS` 에 참조를 추가합니다.
3. 끝입니다. 조회·캐시·폴링·해상도 조절은 자동으로 따라갑니다.

ECOS 항목 코드는 아래로 조회할 수 있습니다.

```bash
curl -s "https://ecos.bok.or.kr/api/StatisticItemList/$ECOS_API_KEY/json/kr/1/300/817Y002" | jq
```

### 주간 모니터링 서식

참고 보고서(Word)의 값을 그대로 옮겼다 — `app/globals.css` 의 `.wk-*` 규칙.

| | 값 |
|---|---|
| 서체 | `fonts/CJ_ONLYONE_FONT/CJ_ONLYONE_300.ttf` (next/font/local, 이 탭에서만 내려받음) |
| 굵기 | 300 파일 하나에 굵게(합성 볼드) — Word 와 같은 방식 |
| 크기 | 헤드라인 14pt · 불릿 13pt · 괄호 보충설명 11pt(보통 굵기) · 줄간격 24pt |
| 색 | 라벨·강조 파랑 `#0000CC`, 본문 검정 |
| 배율 | `--wk-pt: 1.5px` (보고서 1pt 를 화면 1.5px 로) |

문장 안의 `{{…}}` 는 파란 강조, `(…)` 는 작은 보충설명으로 그린다 (`lib/emphasis.ts`).
모델에는 이 표기 규칙과 지난 보고서 원문을 서식 예시로 준다 (`lib/weekly.ts` 의 `SAMPLE_BRIEF`).

### 색

계열 색은 `lib/catalog.ts` 의 `COLOR` 에 모여 있습니다.
파랑 `#2a78d6` / 주황 `#eb6834` / 보라 `#4a3aa7` / 빨강 `#e34948` 조합은
색각 이상(적록·청황)에서 서로 구분되는지 검증한 값입니다.

> 참고한 화면은 초록·주황을 같이 썼는데, 그 쌍은 적록색약에서 사실상 구분이
> 안 됩니다(ΔE 3.2). 그래서 초록 자리에 보라를 씁니다.

한 차트에 두 계열 이상이 겹칠 때만 범례를 그립니다(계열이 하나면 제목이 곧 범례).

등락 색은 국내 관행대로 **상승 빨강(`--up`) · 하락 파랑(`--down`)** 이고,
`app/globals.css` 의 CSS 변수로 관리합니다.
