# /weekly — 주간 모니터링 작성

대시보드 "3. 주간 모니터링" 탭이 보여줄 파일 두 개를 만든다 (YYMMDD-HHMM = 파일을 쓴 날짜·시각 KST, 예 `261110-1405`).

| 파일 | 내용 | 만드는 주체 |
|---|---|---|
| `data/<YYMMDD-HHMM>-weekly-brief.json` | [주간이슈]·[시장반응] 요약문, 참고 기사, 지표 주간 변동 | 이 세션이 뉴스를 읽고 쓴다 |
| `data/<YYMMDD-HHMM>-weekly-market.json` | "[ 주요국 금융시장 동향 ]" 차트 6개(최근 1년)와 환율표 자료, 그 시점 값 `snapshot` | `scripts/weekly-market.mjs` (이력 FRED·ECOS + 실행 시점 시세 CNBC·네이버) |

Claude API 키나 크레딧 없이 이 Claude Code 세션(구독)이 뉴스를 읽고 문장을 쓴다. **지난 파일은 지우지 않는다** —
실행마다 쌓이고(테스트 실행도 남는다), 서버는 접두사(날짜·시각)가 가장 늦은 것을 보여준다. 지난 market 파일들은 화면 오른쪽
"전주比 기준" 드롭다운에 보고 시점 스냅샷으로 뜨고(그 아래엔 최근 14일의 "종가 기준"도 있다), 차트·각주의 변동과 환율표 맨 아래 "직전보고일(M/D일)比" 행은 거기서 고른 시점 대비로 계산된다(기본: 오늘보다 앞선 가장 최근 파일).
차트용 1년치 자료는 `data/market-history.json` 에 쌓여서 실행마다 최근 2주치만 다시 받는다.

실행 요일은 정해져 있지 않다 — 월~금 업무시간 중 상사가 요청할 때(주로 수요일, 금요일일 수도 있다) 실행한다.
인자 `$ARGUMENTS` 가 `YYYY-MM-DD` 면 그 날을 대상 기간의 끝으로 삼는다(지난 주를 다시 만들 때 — 그 날짜엔 시세를 붙이지 않는다).
없으면 **오늘(KST)**: 대상 기간은 오늘 포함 7일이고, 지표 각주·차트·환율표의 최근치는 모두 **실행 시점 시세**다
(사용자 요청: 08:30 고시나 전일 종가가 아니라 `/weekly` 를 치는 순간의 값). 차트의 기준일(x축 오른쪽 끝) = 대상 기간의 끝 = 오늘.

실행 시점 시세의 뜻 — 문장에 쓸 때는 "10일 오전 현재" 처럼 시점을 밝힌다:
- KOSPI · 국고채 3년/10년 · 원달러: 장중(09:00~15:30, 원달러는 02:00 까지)이면 그 시각의 값, 장 마감 뒤면 당일 종가.
- S&P500: KST 낮에는 전날 뉴욕 종가(23:30~06:00 KST 장중이면 장중치). 美 10년물 · WTI 선물 · 환율표 통화는 24시간 거래라 그 시각 호가.
- WTI 시세는 선물 근월물이고 1년 이력은 FRED 쿠싱 현물이라 전주비에 현·선물 차이가 섞인다 — 본문엔 기사 기준(선물) 변동률을 쓴다.
- 화면과 엑셀은 열 때마다 서버가 같은 출처(`lib/market-live.ts`)에서 시세를 다시 받아 최근치에 덧씌운다(60초 캐시, 탭은 5분마다 갱신, 429·403 을 받은 호스트는 15분 조회 중단).
  그래서 파일에 든 시세는 요약문을 쓴 순간의 스냅샷이고 브라우저는 늘 지금 값이다. 서버는 날짜가 가장 늦은 market 파일을 쓰므로
  이력만 새로 받고 싶을 땐 `node scripts/weekly-market.mjs` 만 돌려도 된다.

## 1. 기간·지표

- `node scripts/weekly-indicators.mjs $ARGUMENTS` 를 실행한다. stderr 의 표(한 주 전 → 최근)를 읽어 두고,
  stdout 의 JSON 중 `indicators` 배열은 요약문 파일의 `indicators` 에 그대로 넣는다 (최근치가 시세면 `latest.time` 이 있다).
- `node scripts/weekly-market.mjs` 를 실행한다 (인자가 있었으면 `--as-of <대상 기간 끝>`). stderr 에
  차트 6개의 최근치·지난주·전주비 표와 환율표가 나온다. 이 표도 문장을 쓸 때 참고한다.
- 두 스크립트 모두 최근치를 실행 시점 시세(`scripts/lib/live-quotes.mjs` — CNBC 시세 JSON · 네이버 금융, 키 없음)로 채운다.
  시세는 캐시(`data/market-history.json`)에 넣지 않으므로 그 날짜의 집계치가 올라오면 다음 실행부터 자연히 대체된다.
  집계 지연도 일부 메운다: 美 10년물은 재무부 일별 금리표, KOSPI 는 네이버 일별 시세로 FRED·ECOS 에 아직 없는 날의 종가를 보충한다.
- "⚠ … 실시간 시세를 못 받아" 가 나오면(엔드포인트 변경·차단) 그 계열은 집계치가 최근치다. 그때만 종전 방식으로:
  기사(Bloomberg·美 재무부 금리표 등)에서 확인한 종가로 (1) 요약문 `indicators` 의 `latest` 를 덮어쓰고
  (2) `node scripts/weekly-market.mjs --set sp500=YYYY-MM-DD:값 …` 으로 차트에도 넣는다. 확인이 안 되면 그대로 둔다.
  `--set` 값은 캐시에 남아 다음 주에도 쓰이고, 출처에 그 날짜가 올라오면 출처 값이 이긴다. `--no-live` 로 시세를 끌 수 있다.
- 선이 건너뛰는 날(S&P500 은 FRED 가 2영업일, WTI 현물은 최대 1주 늦다)은 1년 차트에서 거의 보이지 않으므로 그대로 둔다.
- 스크립트 표의 "전주비(7일)"는 7일 전 관측치 대비, "지난 보고比"는 직전 보고 스냅샷 대비다. 화면의 괄호 수치는 후자(사용자가 고른 스냅샷)라서
  문장에 주간 변동률을 쓸 땐 기사 수치를 쓰고, 표의 두 값은 방향 확인용으로만 본다.
- `ECOS_API_KEY` 가 없는 환경(클라우드 routine)이면 FRED 계열만 나오거나 모두 실패한다. 그래도 계속한다 —
  요약문의 `indicators` 를 빈 배열로 두면 서버가 자기 키로 채운다 (차트는 자료가 있는 것만 그려진다).

## 2. 뉴스 수집 (WebSearch, 필요하면 WebFetch 로 본문)

관심 지표: S&P 500, 美 10년물, KOSPI, 원/달러, WTI — 美 주가는 S&P500, 韓 주가는 KOSPI, 유가는 WTI 수치를 찾는다
(기사가 브렌트·나스닥·다우·코스닥 수치만 주면 그 기사는 요지만 쓰고 수치는 다른 기사에서 찾는다). **대상 기간 안의 뉴스만** 쓴다(오늘 장중 움직임 포함 — 지표 표의 최근치가 그 시각 값이다).
출처는 **국제금융센터, Bloomberg, Financial Times, WSJ, Reuters, CNBC** 를 고루 참고한다 — 한 매체에 치우치지 말고
같은 사건을 두 매체 이상에서 확인한다. 최소 다섯 갈래로 검색한다.

1. 국제금융센터 — 목록 `https://www.kcif.or.kr/annual/reportList?mn=001002` 를 WebFetch 로 읽으면 대상 기간의 국제금융속보
   (`reportView?rpt_no=…&mn=001002`)와 "주간 이슈"(mn=001003)가 바로 나온다 — WebSearch(`allowed_domains: ["kcif.or.kr"]`)보다 빠르고 정확하다
2. 해외 통신·방송의 주간 시장 정리 — Bloomberg · Reuters · CNBC + stocks / treasuries / oil / won + 날짜 (매체명을 검색어에 넣는다)
3. 해외 경제지의 해설 — "Financial Times" · "Wall Street Journal" + markets / Fed / Korea + 날짜
4. 지표를 움직인 이벤트 — 연준·금통위·물가·고용·실적·지정학
5. 韓 증시·환율 수급 — 외국인 순매수, 수출업체 달러 매도 등. 연합뉴스·연합인포맥스 등 국내 경제 뉴스로 보충

접근 제약(2026-11-11 확인): `ft.com`·`wsj.com`·`reuters.com` 은 Anthropic 크롤러를 막아 WebSearch 의 `allowed_domains` 에 넣으면
400 오류로 검색 자체가 실패하고 WebFetch 도 안 된다. 검색엔진은 `site:` 연산자를 무시하기도 하니 매체명을 검색어에 넣고 도메인 제한은 두지 않는다.
Reuters 는 전재 사이트(Kitco off-the-wire, The Globe and Mail, Business Standard 등)에서 본문을 읽을 수 있고, Bloomberg 는 본문이 403 이지만
swissinfo 등 전재본이 읽힌다. FT·WSJ 는 검색에 거의 잡히지 않는다 — 제목·다른 매체의 인용 범위에서 참고하고, 못 찾았으면 보고 때 그렇다고 밝힌다.
`kcif.or.kr`·`bloomberg.com`·`cnbc.com` 은 `allowed_domains` 에 넣어도 된다. 수치는 본문을 읽을 수 있는 기사(국제금융센터·CNBC·전재본)로
교차 확인하고, 전재본을 읽었으면 `publisher` 에 "Kitco(Reuters)"·"swissinfo(Bloomberg)" 처럼 원 매체를 함께 적는다.

확인되지 않은 수치는 쓰지 않는다. 추측 금지.

**美 기준금리 인상·인하 확률 수치**는 CME FedWatch(https://www.cmegroup.com/markets/interest-rates/cmegroup-tool-fedwatch.html)에서
**직접 확인한 경우에만** 쓴다(사용자 지시, 2026-11-16). 이 페이지는 WebFetch 로 열리지 않는다(2026-11-16 확인: 응답 없음). 열리지 않으면
확률 수치를 **아예 쓰지 않는다** — 기사가 인용한 FedWatch 수치도 쓰지 않는다(기사 시점의 값이라 보고 시점과 다르다. 실제로 기사 인용치 100% 와
사용자가 직접 본 92% 가 달랐다). 대신 "12월 기준금리 인상 기대 확산"처럼 방향만 쓴다. 수치를 썼다면 `(FedWatch, M/D)` 로 기준일을 붙인다.

## 3. 문장 작성 규칙

`lib/weekly.ts` 의 `SYSTEM_PROMPT` 상수를 읽고 "내용 구성"·"문체 규칙"·"서식 예시"를 그대로 따른다. 요약하면:

- 주간이슈는 그 주 시장 변동성에 가장 큰 영향을 준 이슈 **두 개**. `issue.headline` 은 두 이슈를 한 문장으로(절 하나에 이슈 하나),
  `issue.points[0]`·`[1]` 은 각각 첫째·둘째 이슈의 **상세**(발표 수치, 발언 주체와 요지, 사건 경과, 정책 기대 변화)다 —
  headline 에 없는 제3의 이슈를 적지 않는다(사용자 지시, 2026-11-16). **모든 문장(headline·points·items)은 화면 두 줄 분량**으로
  쓴다(사용자 지시, 2026-11-23 — 한 줄짜리는 너무 단순하다. 날짜·주체·수치·경과를 넣어 채운다). 상자 폭 920px 에 13pt 글자라 한 줄이
  약 42em 이므로 두 줄은 50~84em(공백 포함 약 80~110자)이다. 검증기가 글자 폭을 어림해 한 줄에 그치거나 두 줄을 넘으면 경고한다.
  **예외: `reaction.headline`([시장반응] 라벨 바로 뒤 문장)은 반드시 한 줄**(42em 이내, 한글 약 40자 — 사용자 지시, 2026-11-23).
- **한 문장 안에서 같은 낱말을 되풀이하지 않는다**(사용자 지시, 2026-11-23) — "하락 … 동반 하락"은 "하락 … 동반 내림세"처럼,
  "연속 … 연속"은 "7거래일째 … 이틀 연속"처럼 바꿔 쓴다. 검증기가 한 문장에 두 번 나온 낱말을 경고한다.
- 주간이슈에는 **지표 동향을 쓰지 않는다** — 주가·금리·환율·유가의 수준·변동은 [시장반응]이 따로 쓰므로 중복된다. 이슈 자체의 수치
  (물가 상승률, 실적, 인상 확률 등)만 괄호 안에. `node scripts/weekly-validate.mjs` 가 지표 이름이 보이면 경고한다.
- `reaction.headline` 은 지표 움직임을 인과로 묶은 한 문장, `reaction.items` 는 **원자재 → 금리 → 주가 → 외환** 순서로 각 1문장
  (순서 고정 — 사용자 지시, 2026-11-16. 화면도 이 순서로 정렬한다). **지표 수치는 적지 않는다** — 종가·금리 수준(7,417, 5.13%,
  1,339원, 85달러대, 5,000선)도, 주간 변동폭(몇 %, 몇 bp, 몇 원)도 쓰지 않는다. 차트와 표가 보여주므로 중복이다(사용자 지시, 2026-11-16·17).
  **변동 현황(상승·하락·급락·반등·보합)과 그 배경·이유 중심**으로 쓴다. 원인 쪽 사실 수치(IEA 공급과잉 규모 등)는 괄호 안에 써도 된다.
  검증기가 items 에서 %·bp·원·달러·선·대가 붙은 수나 천 단위 콤마 수를 보면 경고한다.
- **모든 문장은 예외 없이 명사형 종결**("확대", "하락", "차단", "지속") — 사용자 지시, 2026-11-17. "~했다"는 물론 "~잇따라", "~이어",
  "~하며"처럼 동사·부사형으로 끝내지 않는다("발언 잇따라" → "발언 지속"). 시장반응 headline 만 화살표 `{{↓}}` 로 끝낼 수 있다.
  검증기가 끝말을 보고 서술형이면 실패, 동사·부사형이나 조사로 끝나면 경고한다.
- 국가는 한자 약어(美 韓 中), 보충 수치는 괄호 안, 한 문장은 화면 두 줄 분량(약 80~110자), 줄바꿈 없음
- 파란 강조 `{{…}}` 는 `reaction.items` 의 지표 이름과 결과 구절에만. `reaction.headline` 은 화살표만 `{{↓}}`. `issue` 에는 쓰지 않는다.
- 제공된 지표 표의 방향·수준과 문장이 맞아야 한다.
- 금지어(사용자 지시, 2026-11-16): **쇼크 · 레버리지 · 충격 · 매파 · 비둘기파**. "긴축 발언", "완화 발언", "급락", "차입"처럼 풀어 쓴다.
  `weekly-validate.mjs` 는 이 말이 있으면 실패 처리한다.
- 정책금리는 반드시 **"기준금리"** 라고 밝힌다 — "12월 인상"·"금리 인상"이 아니라 "12월 기준금리 인상". "금리"만 쓰면 시장금리다.
  검증기는 "인상/인하"가 있는데 "기준금리"가 없는 줄을 경고한다.
- 주가는 美 S&P500 · 韓 KOSPI, 유가는 WTI 로 쓴다. 브렌트·나스닥·다우·코스닥은 적지 않는다(사용자 지시, 2026-11-11) —
  "브렌트 90달러 하회" 같은 사실은 WTI 수치(종가·변동률·몇 개월 최저)로 바꿔 쓴다.

## 4. 파일 쓰기

`data/<YYMMDD-HHMM>-weekly-brief.json` 을 아래 모양으로 쓴다. YYMMDD-HHMM 은 파일을 쓰는 지금 시각(KST) — `date +%y%m%d-%H%M` 로 확인한다.
실행마다 새 파일이 생기고 지우지 않는다. 서버는 `lib/weekly.ts` 의 `FileBrief` 스키마로 다시 검증한다.
(`data/<YYMMDD-HHMM>-weekly-market.json` 은 1단계의 스크립트가 이미 썼다 — 손으로 고치지 않는다.)

```json
{
  "weekStart": "YYYY-MM-DD",
  "weekEnd": "YYYY-MM-DD",
  "generatedAt": "지금 시각 ISO 8601",
  "model": "claude-code",
  "issue": { "headline": "…", "points": ["…", "…"] },
  "reaction": {
    "headline": "…",
    "items": [
      { "category": "주가", "text": "…" },
      { "category": "금리", "text": "…" },
      { "category": "외환", "text": "…" },
      { "category": "원자재", "text": "…" }
    ]
  },
  "sources": [
    { "title": "기사 제목", "publisher": "국제금융센터 | Bloomberg | Financial Times | WSJ | Reuters | CNBC | 연합뉴스 | 연합인포맥스 | 그 밖의 매체명", "url": "https://…", "date": "YYYY-MM-DD 또는 null" }
  ],
  "indicators": []
}
```

`sources` 는 실제로 읽은 기사 4~8건, URL 은 검색 결과 그대로. `indicators` 는 1단계 stdout 의 배열.

## 5. 검증·보고

- `node scripts/weekly-validate.mjs` 를 실행해 통과할 때까지 고친다 (인자가 없으면 가장 최근 파일을 검사한다).
  경고(문체·길이)도 가능하면 반영한다.
- 결과 문장과 차트 표(1단계 stderr)를 사용자에게 보여 준다. 로컬이면 `npm run dev` 뒤 http://localhost:3000/?tab=weekly 에서
  확인할 수 있고, 차트 아래 "엑셀 파일로 내려받기" 로 같은 내용을 엑셀로 받을 수 있다고 안내한다.
- 커밋·푸시는 사용자가 요청했거나 자동 routine 으로 실행 중일 때만 한다:
  `git add data/<YYMMDD-HHMM>-weekly-brief.json data/<YYMMDD-HHMM>-weekly-market.json data/market-history.json && git commit -m "주간 모니터링 <weekStart>~<weekEnd>"`
